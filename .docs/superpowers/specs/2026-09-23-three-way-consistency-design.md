# 设置区、演示区、CSS 区三处一致（方案 1）

> 状态：2026-09-23 用户确认，同日实施完毕（[progress.md 的 M14 节](../../progress.md#m14设置区演示区css-区三处一致)）。实施计划见 [2026-09-23-three-way-consistency.md](../plans/2026-09-23-three-way-consistency.md)。

## 问题

演示区用单项属性渲染（`flex-grow` / `flex-shrink` / `flex-basis`），CSS 区导出的是 `flex` 简写。
两种写法对某些 basis 的处理不同：简写整条失效时 grow、shrink 一起丢，单项属性只丢 basis，
于是「复制这段 CSS 到项目里」得到的布局与演示区看到的不一样。另外容器宽高只在演示区里有、不在 CSS 区里，
「内容尺寸」混在属性列表里，看不出它不是 CSS 属性。

用户的要求：行为不让用户产生疑惑，入口放在设置区。

## 真实 Chrome 实测：哪些 basis 放进简写会出问题

探针：720px 容器里一个 80px 内容的盒子，分别写 `flex: 2 3 <值>` 与三条单项属性，比较计算值与 `offsetWidth`。

| 类别 | 例子 | 简写 | 单项属性 |
| --- | --- | --- | --- |
| 关键字、长度、百分比、运行期单位、数学函数 | `auto` `content` `0` `100px` `30%` `2em` `10vw` `5ch` `calc()` `min()` `round()` `abs()` | 正常 | 正常，两边一致 |
| 没带单位的非 0 数、拼错的值、负值 | `50` `100pxx` `-10px` `fit-content(100px)` | 整条失效 → `0 1 auto` | 只丢 basis → `2 3 auto` |
| CSS 全局关键字 | `initial` `inherit` `unset` `revert` `revert-layer` | 整条失效 | 只丢 basis |
| 无回退的替换函数 | `var(--x)` `env(x)` `attr(data-x px)` | 计算期整条失效 | 只丢 basis |
| 带回退的替换函数 | `var(--x, 10px)` `env(x, 10px)` `attr(data-x px, 10px)` | 取回退值 | 取回退值，两边一致 |
| **`calc-size()`**（本次新发现） | `calc-size(auto, size)` | `CSS.supports` 为假，整条失效 | 正常生效 |

## 决定

### ① basis 输入框把关

只接受放进 `flex` 简写后与单项属性表现一致的值：关键字（`auto` `content` `max-content` `min-content` `fit-content`）、
`0`、长度、百分比、运行期单位、写法合法的 `calc()` / `min()` / `max()` / `clamp()` / `round()` / `mod()` / `rem()` / `abs()` / `hypot()`。

判定是**保守**的：只收写法确定合法的子集，拿不准的一律拒（终审后补的，见下文「终审补记」）。

拒绝的六类，各自就地说明原因与改法：

| 类别 | 提示 |
| --- | --- |
| 没带单位的非 0 数 | 非 0 数值要带单位，比如 50px |
| 全局关键字 | 全局关键字不能写进 flex 简写，想要默认值请用 auto |
| `var()` / `env()` / `attr()` | 本站没有可供 var()、env()、attr() 引用的值，请直接写长度 |
| `calc-size()` | calc-size() 写进 flex 简写会让整条声明失效 |
| 数学函数写法有误 | 数学函数写法有误：+ 和 - 两边要留空格，结果要是长度或百分比，比如 calc(100% - 20px) |
| 其余浏览器不认的值 | 不是合法的 flex-basis，可以写 auto、content、100px、30% 或 calc() |

- 带回退的 `var()` / `env()` / `attr()` 在 Chrome 里两边一致，**照样拒**：演示区没有可引用的东西，
  写它等于绕一圈写回退值，只会让人以为本站支持自定义属性
- `calc-size()` 不在用户最初确认的清单里，是按同一原则（「放进简写也不失效」）补上的
- 被拒的值不进状态：打字途中只提示、不标红；失焦或回车时仍不合法，就恢复成当前生效的值，提示「……，已恢复为 xxx」
- 分享链接带这类值就整条拒掉回默认，与枚举值不合规同一规则
- 「非法 basis」诊断随之永远触发不了，按零消费方规则删掉

### ② 容器宽高进设置区与 CSS 区

- 属性表加 `width`（200–1200，默认 720）、`height`（120–600，默认 320），面板自动长出两个滑块，与拖拽手柄写同一份状态
- 区间只在属性表里写一份，手柄与分享链接解码都从表里读；`STAGE_LIMITS` 删掉
- 导出的 CSS 在 `display` 之后写 `width` / `height`
- 键盘调尺寸由这两个滑块承担（滑块自带方向键），手柄仍只响应指针

### ③ CSS 区与设置区逐项对应——**不做**

用户决定维持省略初始值：导出的 CSS 短、适合直接粘贴。

### ④「内容尺寸」标明仅用于演示

- 属性表给 `size` 标 `demoOnly: true`
- 设置区在它的名字旁显示「仅演示区」
- CSS 区顶部一行说明：「内容尺寸」只用于演示区，不是 CSS 属性，不会导出（名字从属性表里取）

### 键盘连续调整时的动画——不改

按住方向键连续调滑块时每一步都重建动画，这个现象现有的 gap / grow 滑块同样存在，用户决定维持现状。

用户同意把「三处一致」写进 [CLAUDE.md](../../../CLAUDE.md) 的设计红线，论证放进 [pitfalls.md](../../pitfalls.md)。

## 守卫

1. **basis 分类对拍夹具**：Chrome 实测的候选值表存成 JSON，单测断言「输入框接受的值在 Chrome 里两边一致」，
   并断言每一个被接受的值都在夹具里测过——新增一类可输入的值而不重新实测，测试就红
2. **随机状态对拍**（一次性，结果记进 progress）：随机状态分别按演示区写法（单项属性）与导出的 CSS 文本（简写）渲染，
   逐个盒子尺寸必须一致；混入被拒的值作为探针自证，它们必须测出不一致
3. **变异验证**：每条新守卫声称能拦的回退逐个改坏，确认变红

## 终审补记（2026-09-23）

独立审查在真实 Chrome 里找出一批「收下但简写与单项属性不一致」的值：`0.`（逐字打 `0.5em` 必经）、
`calc(100%-20px)` 等写错的数学函数、`calc(var(--x))` 这类嵌套的替换函数、首尾带 NBSP 的值，
以及能经分享链接往导出的 CSS 里注入整条规则的 `calc(1px)}*{…}`。原来的判定只看最外层函数名、用 `trim()` 去空白，
守卫也只钉住了例子表。修法：

- [basisSyntax.ts](../../../src/core/basisSyntax.ts) 改成保守解析器：只去 CSS 空白；数字按 CSS 语法（小数点后必须有数字）；
  替换函数与 `calc-size()` 嵌在哪一层都拒；数学函数检查 `+`/`-` 两边的空白、类型（结果必须是长度或百分比，乘法至少一边是纯数，除数必须是纯数）与参数个数；
  切不动的字符一律拒。新增拒收原因「数学函数写法有误」
- **不用 `CSS.supports` 做第二关**：会让 core 依赖 DOM（红线 2）；happy-dom 测不出真实语义；各浏览器判定不一，同一条分享链接会解出不同状态
- 守卫改为候选集驱动：[basisSyntax.probe.html](../../../src/core/basisSyntax.probe.html) 入库，在 Chrome 里测 1000 个候选值，
  单测断言「分类器收下的每一个都一致」，并断言收下示例的每个打字前缀都测过
- 面板的回车判断排除输入法组合（`isComposing` 与 Safari 的 `keyCode 229`）：拼音输入法里按回车是上屏，不是提交
